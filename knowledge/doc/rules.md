# Agent Rules

## 1. 安全优先

- 默认只生成只读 SQL，除非环境明确允许且用户明确要求写操作。
- 不要默认暴露敏感字段。
- 在导出全量数据前，先用合理行数的预览查询验证逻辑。

## 2. 指标口径一致

- 指标必须匹配正确的事实表和时间字段。
- 同一轮回答中只能使用一种清晰口径。
- 若指标含义模糊，应先说明默认假设或主动澄清。

## 3. 实体统计要准确

- 业务实体统计优先使用 `COUNT(DISTINCT ...)`。
- 不要把订单明细行当作订单数。
- 不要把每日快照行数当作客户数或商品数。

## 4. 增长率计算规则

- 分子分母必须先汇总再计算。
- 使用 `NULLIF` 处理除零风险。
- 除非业务定义明确允许，否则不要平均预计算增长率。

## 5. 关联关系要清晰

- 只在业务上合理的键之间做关联。
- 优先使用显式 `JOIN`。
- 在写 SQL 前先确认用户要的是订单粒度、明细粒度、客户粒度，还是快照粒度。

## 6. 默认过滤规则

除非用户另有要求，默认：
- 排除测试数据。
- 排除逻辑删除数据。
- 排除取消订单对营收的影响。
- 净收入默认扣除退款影响，除非问题就是分析退款。

## 7. 时间处理规则

- “自然月”按每月第一天到最后一天统计。
- “近 N 天”按滚动日期区间统计。
- 收入类问题通常优先使用 `paid_at` 或 `completed_at`，而不是 `created_at`。

## 8. 输出规范

- 用户只问一个结果时，优先直接给出核心数字。
- 排名结果应说明排序方向。
- 使用默认假设时，需简短说明采用了什么口径。

## 9. 导出规范

- 先用预览查询验证逻辑。
- 大结果集优先使用导出能力，不要把海量数据直接塞进上下文。
- 需要完整明细时，优先走导出文件而不是反复扩大预览查询。

## 10. 文档维护原则

- 企业专属规则必须在验证后再补充进知识库。
- 默认知识库应保持行业中立、可复用、可迁移。
