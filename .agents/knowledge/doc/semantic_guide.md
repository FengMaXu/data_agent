# 数据分析语义理解指引

> 职责：确定“应该回答什么”，形成有依据的 Answer Spec；适用于 SQL、KTX 和后续统计分析。
> 分工：系统提示词与已加载的任务流程 Skill 维护证据优先级、假设登记、版本与交付流程；[SQL 生成规范](./rules.md)维护“如何实现口径”；[业务知识](./business.md)与 [Schema](./db_schema.md)提供具体业务定义和字段证据。本指引不授予业务事实或发布资格。

## 1. 执行步骤（每个新查询任务必读）

1. **拆题**：提取实体名词、指标、限定词、比较关系、时间表达和输出要求，保留对应题面短语。完成条件：字段树的必需字段已建立，未知项明确记录。
2. **定口径**：按第 2 节填写；对会改变结果的合理解释记录依据和影响。完成条件：已知要求与候选假设分开，未决项可定位到字段。
3. **定向取证**：先查适用业务定义及 Schema，再用少量只读探索区分候选解释。完成条件：每次探索说明解决哪个问题、观察到什么、仍不能证明什么。
4. **编排计算**：写出 `输入粒度 → 处理/公式 → 输出粒度 → 后续用途`。完成条件：每次筛选、聚合、连接和比较对身份、总体、权重的影响明确。
5. **对照题意**：从已写查询反译业务含义，按第 5 节用最小样例检查高风险选择。完成条件：题面要求有实现位置，新增行为有依据或明确披露；再按任务流程进入结果执行与交付。

这不是固定次数的探索清单。证据不足时按任务流程处置或澄清；无澄清工具时采用最字面解释并披露，不能将其升级为 Hard Constraint。

## 2. 字段树（每个新查询任务必读）

Answer Spec 按计算顺序分为五段，每个歧义写在它实际发生的那一步。字段写法见 `answer-fields` Skill。

| 段 | 字段 | 必须回答的问题 |
|---|---|---|
| 统计总体 | `population.entity` | 统计什么实体或事件？稳定键是什么？源表一行与业务实体有何关系？同名对象按名称还是按键合并？ |
| | `population.eligibility` | 零值、空值、从未发生活动的实体算不算在内？ |
| | `population.conditions` | 各条件来自哪里？作用于资格总体、事实、指标有效值、聚合结果、窗口后还是展示层？ |
| | `population.source` | 读哪些表或视图？明细表还是汇总表？ |
| | `population.time` | 观察期、基准期、参考日、端点、日历与时区是什么？ |
| | `population.timeField` | 用哪个事件的时间？ |
| | `population.missing` | 缺期补零吗？“上一期”是相邻观测还是相邻日历期？ |
| | `population.joinMultiplicity` | 连接后一行业务对象会不会变成多行？要不要先去重或预聚合？ |
| 度量 | `measure.formula` | 逐层的运算是什么？每层在什么粒度上计算？分子分母、差值方向、量纲是什么？ |
| | `measure.countGrain` | 数行、数实体还是数事件？ |
| | `measure.denominator` | 分母的总体是什么？分母为 0 怎么处理？ |
| | `measure.window` | 滚动或累计窗口从哪里开始、多长？ |
| 分组 | `grouping` | 最终按什么分组、什么日历粒度？比较基准是全局还是组内？ |
| 选取 | `selection` | 按什么排序、取前几个？谁参与排名？argmax/argmin 即取 1 个。 |
| | `selection.ties` | 并列时恰好取 n 行，还是保留切点上的全部并列？ |
| 输出 | `output` | 一行代表什么？标量、集合还是明细？返回哪些列、顺序、单位和精度？ |

一个选择影响多个字段时保持同步，例如改变缺失月份政策可能同时改变时间范围、分母和最终行数。明确未指定、明确不适用与尚无证据，不以技术实现惯例填空。

### S01｜实体身份与比较粒度

- 区分源表行、中间统计对象、被比较对象和最终展示对象，为每一层确定键。例如先比较个人成绩再返回所属组织，不等于先比较组织总成绩。
- 实体数与出现次数是不同指标；重复行可能代表重复上报，也可能代表合法事件、版本或多重参与。
- 名称是展示标签，不天然是实体键。确认同名异人、别名与历史版本是否应合并；代理键若稳定地一一对应业务实体，可以使用，不能仅因它是代理键而拒绝。
- “每个”“各地区内”“跨所有地区”约束不同的分组与比较范围。卖家自己的代表商品应在卖家范围内计算，除非明确要求重复展示全局共同基准。

**完成条件：** 能解释每阶段“一行代表什么”，名称投影没有偷偷改变实体身份。

### S02｜总体、分母与缺失

- 分别定义资格总体、指标有效总体、展示总体；为每个均值和比例写出分子分母的集合、时间范围与计数单位。
- 区分全部客户与活跃客户、共同观察期日均与实体活跃日日均。事实表中出现的对象不自动等于业务全集。
- 缺失可能是零活动、未知、未上报、不适用或尚未入组。只有已确认是零活动时才补零；构造实体×日期全集时限制各实体可观察期。
- 后续指标缺失不自动影响前面的入选总体。例如热门技能可由全部相关职位选出，再在对应职位中按已定义政策计算薪资。

**完成条件：** 能说明加入零活动对象或删除缺值记录分别改变哪个分母，以及这种变化是否得到业务支持。

### S03｜连接关系与权重

- 先确认左右粒度、完整业务键、预期基数与未匹配政策。复合键遗漏一列即可把不同事件误配。
- 多事实表直接连接可能把两侧度量相互复制；先确定共同统计粒度，再决定是否分别聚合后连接。
- 重复维度先区分脏重复、有效历史版本和合法多值。任意挑一条与整体去重都不是默认正确方案。
- 连接后的均值可能按事实数量加权，而不是按客户、区域或商品等权。即使结果行数符合预期，也要检查权重。

**完成条件：** 行复制、未匹配剔除与权重变化均能从业务关系解释；实现方式见 SQL 规范。

### S04｜指标计算图

- 聚合顺序属于指标定义。“三个最高销量产品的平均年销量”：产品年销量 → 选产品 → 平均所选年销量，而不是平均所选产品的原始明细行。
- 明确平均比率、汇总值之比、组均值的等权平均与加权平均的区别；中位数同样必须定义观测集合。
- 极值及其所属日期、比赛、地点必须来自同一个被选对象。复合指标所有分量合成后再排名。
- 列举的多个条件指标分别保留，例如第一、第二、第三偏好分别计数。
- 指定季节调整、回归、加权预测等模型时保留完整计算链；数据或能力不足时说明限制，取得授权前不替换成原始总额或简单均值。
- 预测累计值必须满足业务单调性：预测值不低于最新已知累计值；同比套算违反该约束时，改为从最新累计值向前叠加未来增量。

**完成条件：** 每个阶段与题面短语对应，最终指标的全部分量、分母和权重可追溯。

### S05｜条件作用域与量词

- 每个条件标记其作用阶段；提前执行可能改变资格总体、排名候选或基准期。
- “买过 A 的人还买什么”先定义人群，再明确其他购买属于同单、同会话、指定期间还是全历史；人群重合不等于同订单共购。
- “首次任职后在某地活动”先求全局首次任职；“首次在某地任职”才在地方范围求首次。
- 区分存在一次、每次、至少 k 次、占比达到阈值和连续 k 期。“持续”“稳定”本身不足以确定其中一种。
- 排除首期展示不自动取消它的比较基准资格。保留零活动对象时，也要检查后续条件是否又将其排除。

**完成条件：** 每项条件都能回答“筛掉谁、在哪一步、为什么在那里”。

### S06｜时间事件与基准

- 区分下单、支付、发货、交付时间。“已交付订单按月”可能是状态筛选加下单月份，也可能按交付事件月份；结合完整题面和证据确认。
- 明确自然年/财年、季度映射、时区和参考日；样本最大日期不自动成为年龄或任期参考日。
- 区分全局最新、各实体最新、最近完整期；首任职日期等基准也要明确在全局还是子群内求取。
- 将 period 0、period 1 展开为具体检查日期，核对首末期；明确任期/有效期起止端点是否包含。

**完成条件：** 时间定义可以展开为具体日期或时间戳及其包含关系，没有依赖隐含日历约定。

### S07｜连续性与窗口

- 相邻观测不等于相邻日历期；缺一个月时，不能把跨月跳跃自动当作环比。
- 区分 N 条记录与 N 个自然日，是否含当期、是否允许部分窗口、首个有效窗口和平均分母。
- 补齐周期前使用 S02 的缺失政策；先保留比较基准并计算变化，再筛最终展示期。
- 前后窗口中的事件当天或事件周要明确归前、归后还是排除，不能默认丢弃边界期。

**完成条件：** 至少能写出缺一期、首个有效期和边界当天/周三个样例应包含的日期集合。

### S08｜排名、并列与分桶

- 先定义候选总体、比较实体、指标、分区、方向、数量及并列政策。作品数、销量和租赁热度不可互换。
- 区分恰好 N 个对象与前 N 名含并列；并列裁决需要依据，合格对象不足时不补造。
- 业务并列与稳定展示是两件事；额外排序键不能擅自消除并列。
- 等人数分桶、累计排名比例、等宽区间与分位点分类不是同一种定义；有公式按公式执行。

**完成条件：** 并列极值、分桶边界和不足 N 个对象时的预期行为明确。

### S09｜事件序列与终止

- 先确定真实事件粒度，再计算先后；同一事件的多条组织/明细记录不自动代表多次发生。
- 使用真实时间和有业务依据的顺序键。物理存储顺序不是事件时序；同刻的稳定排序也不证明真实先后。
- 同时间戳先区分重复上报与不同事件；顺序无法判断时明确披露，不能用任意 ID 排序冒充已知时间关系。
- 首尾属性从实际参与事件求出；现成首场/末场标记需确认定义一致。
- 序列终止可能是应统计的 END 类别，而不是应删除的空记录。

**完成条件：** 重复、同刻、单次事件与终止都有明确解释。

### S10｜状态、分配与递归

- 区分事实输入、原始累计状态、业务转换状态与展示值。展示余额设下限不自动意味着每日把原始余额截断后递推。
- FIFO 保留需求行顺序、库存批次顺序和此前已消耗数量；下一需求不能从同一原始库存重新分配。
- 递归明确统计路径、边、唯一叶子还是实际物料出现次数；同叶子多路径可能合法累加，也可能重复，不能一律相加或去重。
- 确认路径倍率、根节点资格与循环政策；实现限制触发时不能把截断结果冒充完整答案。

**完成条件：** 用负余额后转正、多需求共享库存、多路径同叶子等适用样例区分候选算法。

### S11｜异常与排除

- NULL、unknown、零、负数、反向日期和终止标记分别解释；不统一视为无效。
- 清洗与排除必须有业务依据；记录它们对实体、金额、分母和排序的影响。例如收入类指标按业务定义排除退款或无效状态，并在数据源层（连接/筛选阶段）完成。
- 某个业务库的状态值、枚举和规则只在该库内有效，不迁移到其他数据库或评测库。
- 关联指标使用一致的事实归属关系，例如租赁数与支付额遇到重复或孤立支付时先解决归属。
- 题面明确排除某类事件时，使用对应事件证据实现；名次变化不天然等于超车，需要处理已明确排除的进站、退赛等影响。

**完成条件：** 异常处理是已记录的业务选择，不是为得到好看的结果而临时加条件。

### S12｜公式、单位与精度

- 逐项标明输入、中间和输出单位。区分比例 `a/b`、百分数 `100*a/b`、相对变化率 `100*(new-old)/old` 与百分点变化 `100*(p_new-p_old)`。
- 比例默认保留 0–1；是否要求 0–100 的百分数依据题面或业务文档确认，不静默乘以 100。
- 零分母、无数据与有效零值分别定义；无定义的增长率不自动变为 0。
- 题面给出分量公式时按原式计算。例如对年/月/日分量分别取绝对值，不等于另一种完整日期差算法。
- 分类的定义区间端点不同于样本最小/最大值；开闭端点按定义保留。
- 默认保留中间精度；明确要求中间舍入时按指定阶段执行，并确认排名使用舍入前还是舍入后数值。

**完成条件：** 量纲、边界与舍入阶段明确，跨月、闰日或反向日期等适用样例可解释。

### S13｜输出契约

- 从题面确定行粒度、列清单、行数政策、排序、格式和精度；内部业务键与最终名称/ID 投影分别处理。
- 验证所需分母、计数和排名不自动成为用户要求的输出列；标量问题要完成最终聚合或选择。
- 区分无符合对象、数据不足、查询失败与有效零值；不默认将空结果改成一行零。
- 未指定的格式可以作展示选择，但不能标为用户硬性要求；参考答案的列和行数不能替代题面契约。

**完成条件：** 每个输出字段和每类输出行都有任务依据。

### S14｜跨期实体集合与未匹配期间

- 先用稳定业务键和各期资格条件分别定义实体集合。明确比较总体是共同实体、基准期锚定、目标期锚定、各期并集还是业务定义全集；这些是不同口径，不能由 `INNER JOIN`、`LEFT JOIN` 等实现惯例自动决定。
- 区分实体在某期缺席、存在记录但指标为 NULL、已确认零活动和分母为零。只有业务证据确认缺失代表零活动时才补零；无定义的变化率也不自动变为零。
- “增长率需要两期有效值”只定义增长率的有效集合，不自动定义后续均值、比例或预测的资格总体。分别说明每期集合、变化率有效集合与最终聚合分母。
- 多期比较说明使用所有期间均存在的固定面板，还是按相邻期间分别确定总体；同时记录新增、退出和不可观察实体对分子、分母、权重及最终行数的影响。
- 可比较各期实体数、共同成员数及仅单期出现的成员，以确认选择是否具有实质影响；这些 observed data 只能证明集合不同，不能自行裁决应采用哪种总体。
- 最终连接、透视和缺失处理必须实现已记录的集合政策。证据不足且选择会改变答案时，将歧义中立地写成受影响字段的待定候选，并按系统流程澄清或披露，不把其中一个候选先写成既定答案。

**完成条件：** 每个比较期间的实体集合、变化率有效集合、未匹配期间政策及其对指标分母和输出的影响均可说明，SQL 连接方式没有新增未经支持的总体假设。

## 4. 歧义澄清模板

只问会改变答案、且不能由权威证据解决的选择。推荐：**“这里的 X 是按 A 还是 B？两者会改变 Y（总体/分母/基准/排序）。”** 不要求用户在技术函数之间选择。

| 表达 | 优先区分 |
|---|---|
| 平均、日均、人均 | 什么粒度等权、是否加权、全部对象还是活跃子集 |
| 最新、最近 | 全局最新、实体内最新、最近完整期、指定截至日 |
| 持续、稳定、经常 | 每期、连续若干期、次数阈值、占比阈值 |
| 最好、热门、最差 | 比较哪个实体、哪个指标、哪个方向 |
| 一起买、还买过 | 同单、同会话、指定期间、全历史 |
| 变化、提高、下降 | 绝对差、相对变化率、百分点 |
| 去年同期、同比 | 上年同月、上年同期累计 |
| 唯一、去重、次数 | 实体、事件、显示值、路径出现次数 |

### 候选对照（决定待定字段前必做）

先看探针输出：各候选输出相同的待定字段不影响答案，系统视为等价，不必对照。输出不同时才需要对照。

题面措辞的存在不等于它支持某个候选。决定之前，把每个候选放回题面逐词检验：

1. 列出题面中约束该选择的短语：实体名词、事件动词、范围词（每个、各、跨所有、全部、总计）、比较词和输出词（找出、列出、分别）。
2. 对每个短语判断它支持、排除还是不区分各候选；只有至少一个短语排除了其他候选，才算有区分力。
3. 常见对照：
   - 事件决定时间字段：统计某事件的量（如“已送达订单按月”），默认用该事件发生的时间，而不是流程中的其他时间。
   - 范围词决定粒度：“跨所有 X”“整体”对应全局一个结果；“每个 X”“各 X”对应按 X 分行。
   - “总额、总计”默认包含该实体完整金额的各组成部分；只有题面或业务文档明确排除时才去掉。
   - 输出词决定行数：“找出最……的那个”对应一行；“列出、分别”对应多行。
   - 总体词决定是否纳入零值实体：“每个出现过的”与“全部已定义的”不同，按题面的主语和动词判断。
4. 写下对照结论：哪个短语排除了哪些候选。它就是决定理由（rationale）；写不出排除理由时先请求比较，再按最符合题面的候选决定，未证实的决定会被披露。

## 5. 有条件验证与完成检查

选择能区分解释的最小反例，而不是重写一遍同一假设：同名不同 ID、缺月、并列第一、零活动对象、需求共享库存等。预期性质从题意或业务定义推导，不从当前 SQL 反推。

不变量必须写明前提：互斥且完备分类才应计数守恒；一对一且不筛事实的连接才应保持原始总额；库存守恒需确认计量单位和允许的业务调整；固定等宽有序区间才应满足相应边界约束。

- [ ] 对象和键、资格总体、分子分母与权重有依据。
- [ ] 聚合、连接和筛选的作用阶段符合题意。
- [ ] 时间基准、缺期、首末边界和并列政策明确。
- [ ] 跨期比较的各期实体集合、变化率有效集合、未匹配期间政策及其对分母、权重和输出的影响已明确。
- [ ] 顺序、异常、状态或递归政策已按适用专题处理。
- [ ] 全部公式分量与输出字段已覆盖。
- [ ] 剩余歧义、未检查项和覆盖限制已记录；新证据按系统流程修订 Spec。
