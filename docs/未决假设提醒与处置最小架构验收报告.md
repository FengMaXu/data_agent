## 1. 结论

2. unresolved reminder 支持 revision/hypothesis-set 去重、独立开关、fail-open 和每任务最多三次的当前代码约束；

7. 根据后续用户授权，当前工作树已追加 exploration observation evidence handle、assumption profile/vector 一致性校验和 material population stable-order guard；定向与 Runtime 全量测试通过，但尚未执行新的 Spider2 A/B，因此不能声称正确率提升；

不能确认：

1. 最新低层阻塞加固后的完整 10 题 Treatment 指标；
2. 最新版本相对 Control 的正式同配置 A/B 净收益；

## 6. Phase 3：Disposition、Result Boundary 与交付绑定

### 已实现

Disposition 派生：

- 无可信 Verification/Decision → `unresolved/unhandled`；
- provisional Decision 选择 → `provisional_selected/handled`；
- 用户确认 → `user_confirmed/handled`；
- 形式规则支持 → `evidence_supported/handled`；
- 反驳 → `rejected/handled`。

当前协议的阻塞点：

1. Agent `query_database(mode=result)` 包装层；
2. `InMemoryQueryAssurance.recordPreview(mode=result)`；
3. `convergeCandidate()` 在物理 result SQL 前；
4. `publishCandidate()` 在 promote 前；
5. CSV stream 重执行前检查当前 revision，而不是只检查旧 Artifact 快照；
6. inline publish 同样检查当前 revision。

旧 schema-v2/legacy Spec 中持久化的 `evidence_supported`、`user_confirmed`、`rejected` 状态会兼容投影为 handled，不会因缺少迁移 Verification 被错误降为 unhandled；当前模型工具仍只能提交 `candidate`，不能自报可信状态。


覆盖包括：

- unhandled result SQL 的数据库调用数为 0；

- 注入旧 Artifact 后 `publishCandidate` 的 promote 调用数为 0；
- stale/current revision 在 CSV stream 前失败；
- Decision 处置后 Result Artifact、Receipt、Disclosure 精确绑定；

## 11. 残余风险与处置建议

1. **人口总体仍不可自动判真。** local061 已从静默错误升级为显式 provisional Decision，但没有获得 Gold 口径证据。
2. **Decision 形式主义。** Agent 可为每个 hypothesis 快速生成 alternatives；如果 assumption vector 无法区分，最终仍依赖稳定排序。
3. **派生 CTE 覆盖缺口。** 当前 bounded population detector 对透视后 NULL 排除、年度集合交集等隐式总体变化覆盖不足。
4. **成本显著。** reminder-only Treatment 的 mean token 增加 67%，mean latency 增加 61.9%，而正确率不升。
5. **Harness 指标不一致。** local029 的 Receipt 与 SQL/CSV extraction 不一致，应继续分列报告。
6. **不要用 Gold 反向硬编码。** local061 的正确总体不能写成题型专用规则；只有出现可泛化、可高精度观测的证据算子时才考虑升级。

建议维持当前最小架构，不扩展提醒复杂度。若未来允许继续评测，只需补齐**一次**最新工作树的固定 10 题 Treatment，与已有同版本 Control 配对；不得逐题重跑或拼接。但本报告不启动该运行。
