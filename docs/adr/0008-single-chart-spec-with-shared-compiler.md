# 统一 ChartSpec 与同构编译器，按目标选择渲染器

本 ADR 提议把聊天图表、看板和报告的绘图收敛为一种可序列化的图表描述和一套共享编译逻辑，并取代报告中由模型编写 Python/matplotlib 绘图的路径。数据获取、聚合口径与发布规则仍按 ADR-0001、ADR-0003 执行；看板实时数据绑定的具体机制留待 v3/v4 合并时另行决策。

## 背景

同一张图目前分散在四条路径上：

| 场景 | 当前路径 | 问题 |
| --- | --- | --- |
| 聊天图表 | `show_widget` 只接受 `kpi`、`chart`、`table`、`steps`（`packages/runtime/src/tools/core.ts`）；前端 `WidgetRenderer` 另保留 `echarts` 分支并直接 `setOption(widget.config)`，`raw_svg`、`raw_html` 仅存在于类型声明 | 模型当前不可达 `echarts` kind，但前端仍有一条不经校验的 option 兼容入口；表格格式化会在语义文本命中时按“绝对值 ≤ 1”推断百分比尺度 |
| 静态看板 | `dashboard-v3.ts::chartOption` | 只支持 bar/line/scatter 加一个写死的 pie；显式 series 路径按类别求和，缺失值按 0 计入；旧路径虽可配置 `aggregate`，但聚合仍发生在绘图层；标签无布局策略 |
| 实时看板 | `dashboard-v4.ts` 声明 line/bar/pie/kpi/table 五种视图 | 当前 HTML 主要是语义刷新桥接壳，未实现完整视图渲染；与 v3 各自一套描述 |
| 报告 | `demo-report`、`analysis` skill 经 `run_python` 用 matplotlib 出 PNG | 项目没有统一记录绘图代码、依赖、数据来源和展示处理规则；样式与字体由模型临场决定，难以复现和披露 |

此外，`renderStandaloneDashboardHtml` 把编译后的 option 经 JSON 序列化嵌入 HTML，option 中的函数（tooltip、轴标签截断、时间格式化等 formatter）会被静默丢弃。任何产出函数型 formatter 的编译器（包括候选的 Flint）在这条路径上都会退化。

Flint Chart（microsoft/flint-chart，MIT，评估版本 0.5.1）提供语义类型驱动的模板与布局计算，其 ECharts 后端有 33 个模板。评估见 `docs/research/flint-chart-dashboard-fit.md`。它的 ECharts assembler 会按编码聚合、在溢出时筛选绘图数据，不消费 `theme_spec`，且 0.x 版本 schema 尚不稳定。

## 决策

### 契约

1. **唯一图表契约。** 在 `packages/contracts` 中以 typebox 定义带版本号的 `ChartSpec`。新生成的聊天图表、看板视图和报告图表只使用这一种结构。它描述图种（mark）、字段编码（x、y、series、size 等）、排序、标题，以及第 3 条所需的数值语义。
2. **编译器不得隐式合并观测或改变指标含义。** ChartSpec 不含数据变换与聚合；输入数据必须已处于图表所需粒度，聚合属于查询，由 Query Assurance 负责。唯一性约束按图种定义：
   - 类别柱图、热力图等要求编码组合唯一的图种，出现冲突时返回结构化错误；
   - 折线图要求同一系列、同一时间点至多一个值；
   - 散点图允许重复坐标，需要区分观测时使用独立的点身份字段。

   任何情况下都不得以去重、求和或平均修复冲突。
3. **数值语义必须显式声明，不依赖猜测。** 字段须声明存储尺度与显示尺度（如 ratio 存储、percent 显示），以及单位；日期须声明粒度，渲染不得因浏览器与 Node 的时区差异产生偏移；空值保持为空值，不转为零。这些信息优先取自数据集元数据，由 ChartSpec 引用，不要求模型重复填写。元数据缺失或冲突时返回结构化错误，不按数值大小推断尺度。编译器只做声明范围内的显示单位换算，不做业务指标计算。

### 数据身份

4. **数据引用与交付资格由 Runtime 负责。** 图表块通过数据集引用取数，而不是由模型直接提供 rows。Runtime 解析引用、检查交付资格，再把数据交给编译器；编译器不承担发布授权。静态交付绑定不可变的数据版本，而不是可被覆盖的文件路径。Python 派生数据须保留输入结果引用与计算来源，不得冒充原始已发布查询结果。上游结果的 Disclosure 与第 6 条的展示提示一并交付，后者不能替代前者。

### 编译与展示

5. **同构编译逻辑 `@data-agent/charts`。** 纯 TypeScript，确定性，可在浏览器与 Node 中运行。接口形如 `validate(spec, dataset)` 与 `compile(spec, dataset, { target, size, theme }) → { option, notices }`。各渲染目标共用同一编译逻辑与语义约束；因 target、尺寸、字体度量不同，产物不要求逐字节相同。主题（配色、字体、间距）集中在此包中，取代 `dashboard-v3.ts` 中写死的调色板和 skill 中的口头样式约定。
6. **展示处理分三类，并以展示提示（Presentation Notice）告知：**
   - **布局处理**：标签旋转、截断、字号调整。低干扰呈现。
   - **视口处理**：滚动、分页、缩放。不改变底层数据，须说明当前可见范围。
   - **数据选择**：Top-N、排除行、合并“其他”。编译器默认不得因画布不足删除数据；确需选择时，必须由 ChartSpec 显式声明策略（排序、范围、适用图种、分母口径），并持续显示所选范围及完整数据的获取方式。“其他”等需要计算的合并项不在编译器中隐式完成，只能来自已声明来源的数据。

   展示提示与 CONTEXT.md 中的 Disclosure 是不同概念：Disclosure 记录查询结果发布时的未决观测，展示提示记录图表对结果的呈现方式，二者在交付层合并呈现。图表刷新、导出或尺寸变化后，展示提示须重新计算，不得沿用过期内容。
7. **Flint 只作为编译器内部的可替换后端。** 若采用 Flint 模板，必须通过适配器关闭其聚合功能，并把其 overflow 处理纳入第 6 条的分类，不允许静默筛选数据。Flint 的 `chart_spec` 不作为持久化契约，也不暴露给模型；更换或移除 Flint 不得改变 ChartSpec。是否采用由实施阶段的对比评测决定，验收以数值、观测身份与分母一致为准，而不只是 warnings 可见。

### 渲染与持久化

8. **按目标选择渲染器：**
   - **应用内（聊天、看板）**：前端组件在浏览器中调用编译器并渲染 ECharts。
   - **独立 HTML 看板**：内联打包后的编译器与 ECharts，页面嵌入 ChartSpec 与数据，而不是 option。
   - **静态（报告、缩略图）**：首选 Node 端 ECharts SSR（`renderer: "svg"`、`ssr: true`、`renderToSVGString()`）输出 SVG，需要位图时用 `@resvg/resvg-js` 转 PNG，不依赖浏览器或 Python。该方案以中文字体、长标签、固定尺寸和目标图种的实测通过为接受条件。
9. **不以 ECharts option 作为持久化源。** 持久化的是版本化 ChartSpec、不可变数据身份，以及编译器与主题的版本信息。已交付的报告同时保存导出的 SVG/PNG 产物，不因主题或编译器升级而静默变化。ChartSpec 契约版本与编译实现版本分别管理。重现保障的是数值与语义一致，不承诺跨画布、跨目标的像素级一致。
10. **报告由文档块与图表块组成。** 图表块为 `{ chart: ChartSpec, dataset: <数据集引用> }`，导出 md/docx/pdf 时由 runtime 统一渲染，并把 Disclosure 与展示提示写成图注。Python 仅负责统计计算，其输出按第 4 条作为派生数据集交给 ChartSpec，不再绘图。

### 迁移与边界

11. **收紧兼容入口，历史内容不静默改变含义。** 前端的 `echarts`/`config` 分支只渲染 Runtime 产出的可信内容；信任来源于 Runtime 的产出记录，而不是模型可填写的标记。该限制落实在 Runtime 校验中，而不只写在 skill 文案里。历史会话与看板采用明确的兼容读取或迁移：能无损迁移的转为 ChartSpec；不能无损迁移的返回结构化说明，保留原样只读展示或提示不支持，不得静默改变图义。v3 现有的多系列、系列分组、混合 mark、多轴绑定与系列筛选，须在迁移前逐项确定保留或暂不支持。
12. **xlsx 原生图表是预留渲染目标，不在首期范围。** Flint 的 Excel 后端依赖 Office.js 宿主，不能在 Node/Electron 中产出 .xlsx 文件；项目目前也没有 xlsx 输出。出现可编辑 Excel 交付物的明确需求时，新增 `xlsx-native` 目标：支持的图种写入数据区与原生图表，不支持的回退为嵌入 SSR PNG 并附展示提示。实现可选 runtime 自带固定脚本调用 XlsxWriter，或由 TS 直接生成 DrawingML，均不得让模型编写代码。原生图表绑定可编辑单元格，交付时须标明其为可编辑副本，而非已发布结果本身。

## 实施与验证

按以下顺序推进，每步独立可交付：

1. 定义 ChartSpec schema，建立 `@data-agent/charts`，先覆盖现有 bar、line、pie、scatter，并逐项列出 v3 表达能力的保留情况。
2. 报告静态出图改走 SSR，替换 `demo-report` 与 `analysis` skill 中的 matplotlib 路径。
3. 聊天 widget 改用 ChartSpec，执行第 11 条，并把 `WidgetRenderer` 的百分比尺度推断改为第 3 条的显式声明。
4. 合并 v3/v4 看板为单一看板规格：views 由 ChartSpec、Table、KPI 组成。实时数据绑定（数据版本、更新时间、刷新后的重新校验与提示更新）另立 ADR。
5. 扩展图种。以同一批已发布数据对比自研模板与 Flint 适配后端，覆盖行业柱图、月份折线、分组柱图、散点、热力图；测试中文长标签、负数、空值、空结果、高基数、百分比尺度、固定画布和离线 HTML。

接受本 ADR 前须有对应测试的验收原则：

- 未获交付资格的数据引用不能经由图表入口交付；Python 派生数据保留来源标识。
- 编译器不合并观测：合法的散点重复坐标既不报错也不合并；饼图与高基数处理不静默改变分母或数据范围。
- 数值语义显式：同一数值在 ratio 与 percent 声明下分别正确显示；空值不变为零；日期不因时区偏移。
- 跨目标一致：同一数据版本在聊天、独立 HTML、SSR 中数值与单位一致。
- 历史可追溯：历史会话与看板有明确的读取或迁移结果；主题或编译器升级后，已交付报告仍保留原始产物与版本信息。

需先解决的技术约束：

- **中文文本测量**：Node 端 SSR 默认只能估算文本宽度，须通过 `echarts.setPlatformAPI({ measureText })` 注入基于真实字体的度量。
- **字体分发**：resvg 需显式传入字体文件；随应用分发 CJK 字体子集，不依赖系统字体。
- **原生依赖**：resvg 及可能使用的 canvas 模块是 napi 二进制，须纳入 electron-builder 打包与 `smoke-electron` 冒烟测试。

## 考虑过的方案

- **在现有 `dashboard-v3` 上接入 Flint**：改动最小，但仍保留多套描述；option 序列化会丢弃函数；报告仍依赖 Python，问题没有根治。
- **以 Flint `chart_spec` 作为契约**：省去一层映射，但把 0.x 外部 schema 变成需要长期持久化的格式，并把后端切换的成本转嫁给已保存的看板和报告。
- **以 Vega-Lite 作为契约**：生态成熟、模型熟悉，SSR 同样可行，也可以通过受限契约禁用 transform/aggregate。但禁用后其相对 ECharts 的主要优势（完整的图形语法）不再适用，而项目的前端与看板已基于 ECharts，切换只增加迁移成本。
- **保留 Python/matplotlib 做报告图**：通过统一记录代码、依赖与数据来源同样可以做到复现和披露，但会与交互图形成两套样式、两套语义约束和两套校验，需要同时维护。
- **用无头浏览器截图生成静态图**：可复用前端渲染，但给桌面分发引入浏览器依赖和额外启动成本；只在 ECharts SSR 实测不达标时作为后备。

## 后果

- 同一张图在聊天、看板、报告中外观与口径一致，样式修改只发生在一个包中。
- 口径与尺度问题从静默求和、按数值猜测，变为编译期的结构化错误；对数据的任何选择都显式声明并持续可见。
- 模型需要学习的绘图接口减为一种，且不再编写 ECharts option、HTML 或绘图代码。
- 数据集元数据需要承载尺度与单位信息，这给查询结果发布增加了元数据责任。
- 已交付报告需额外存储导出产物与版本信息。
- Python 运行时可在迁移完成后移除 matplotlib，缩小分发体积。
- 新增 napi 原生依赖与字体资产，增加打包与冒烟测试负担；独立 HTML 看板需内联编译器，体积比只内联 ECharts 时更大。
- ChartSpec 的表达力有意受限；超出其范围的图需扩展契约与模板，而不是让模型绕过契约。
- CONTEXT.md 需在本 ADR 接受时补充 ChartSpec、数据集引用与展示提示（Presentation Notice）三个术语，并注明展示提示与 Disclosure 的区别。
