# 绘图模块转交文档

更新时间：2026-09-29。对应 `develop` / `master` @ `6f872dd`（#89 合入之后）。

本文面向接手绘图模块的开发者或 agent：说明设计依据在哪里、已经做到哪一步、哪些约束不能破坏、下一步做什么，以及开发中踩过的坑。**文中凡是与 ADR 或设计草案不一致的地方，以代码为准**，分歧集中列在第 6 节。

## 1. 概述

聊天图表、报告图表和（将来的）看板统一使用一种可序列化的图表描述 **ChartSpec**。ChartSpec 由一个同构编译器 **`@data-agent/charts`** 编译成 ECharts option：浏览器端直接渲染，报告则通过 Node 端 ECharts SSR 输出 SVG。图表数据只能来自**已发布的查询结果**，读取时经发布记录（Receipt）鉴权。编译器不聚合、不合并观测、不把空值当 0、不自行删减数据；对展示方式所做的处理以**展示提示**（Presentation Notice）返回。

## 3. 架构与代码位置

## 5. 不能破坏的约束

这些是 ADR-0008 的核心，也都有测试覆盖。改动编译器或渲染器时逐条确认：

1. **编译器只显示数据集中存在的数值。** 不聚合、不合并观测：类目图同一格有多行时返回 `DUPLICATE_KEY`；散点图允许重复坐标。唯一的例外是部分与整体图种（堆叠、百分比堆叠、饼图）固有的视觉求和与占比，要求度量**可加、完整、非负**，否则分别返回 `NON_ADDITIVE_PART_OF_WHOLE`、`INCOMPLETE_PART_OF_WHOLE`、`NEGATIVE_IN_PART_OF_WHOLE`。
2. **数值语义显式声明，不猜。** 度量字段必须声明 `type: "quantitative"`、`storage`、`additivity`；缺失时返回 `SEMANTICS_MISSING`。不按数值大小推断百分比，不按列名推断可加性。空值不转为零（折线断开、柱留空，并给出 `NULL_VALUES` 提示）。
3. **不自行删减数据。** 数据选择只能通过显式声明的 `selection: top_n`，而且不能与部分与整体图种同时使用。静态图放不下时返回 `CAPACITY_EXCEEDED` 并附修正建议，不裁剪。
4. **数据只来自已发布结果。** `render_chart` 与 `show_widget(chart)` 都只接受 `data.kind = "publication"`，经 `ArtifactDirectory.resolveRows` 鉴权并校验 `contentHash`。模型不能再把数据行写进图表 spec。
5. **不持久化 ECharts option。** option 只在内存中存在；聊天 widget 持久化的是 ChartSpec 与行数据，浏览器每次重新编译。
6. **历史内容不静默改变。** 没有 `contractVersion` 的旧 chart 和 table 保持原来的渲染（包括旧表格的百分比推断）。
7. **模型上下文里不放行数据。** `show_widget(chart)` 返回给模型的是摘要；物理画像不进入 `inspect_answer` 的模型可见文本。
8. **静态 SVG 必须是合法 XML，且输出确定。** 字体栈用单引号；zrender 生成的 id 只在属性和选择器位置按内容重命名（见第 9 节）。

## 6. 与 ADR 和草案的分歧（以代码为准）

| 项 | 文档中的说法 | 实际实现与理由 |
| --- | --- | --- |
| 中文字宽 | ADR-0008 技术约束原写：须通过 `setPlatformAPI({ measureText })` 注入真实字体度量 | **未注入。** ECharts 不依赖 canvas 的默认估算（汉字按 1em，拉丁字符查内置宽度表）与中文字体的实际显示一致；用中文长标签实测截图后确认没有溢出或重叠。ADR 已据此修订 |
| 散点重复坐标 | 草案第 5 节：声明了 `id` 时才允许 | 散点一律允许重复坐标（按 ADR-0008 决策 2）；`id` 只标识观测 |
| 错误码 | 草案列出 12 个，含 `BIN_OVERLAP`、`FLOW_CYCLE`、`RANGE_INCONSISTENT`、`STAT_ORDER_VIOLATION`、`SEMANTICS_CONFLICT` | 实现 11 个：新增 `SCHEMA_INVALID`、`VALUE_NOT_NUMERIC`、`INVALID_ENCODING`、`INVALID_SELECTION`。草案中的直方图、桑基图、瀑布图、箱线图相关错误码要等对应图种实现；`SEMANTICS_CONFLICT` 要等数据集注解实现 |
| 部分与整体遇到空值 | 草案未规定 | 判为 `INCOMPLETE_PART_OF_WHOLE` |
| 饼图 | 草案 `donut?: boolean` 未定缺省 | 缺省画环形，与 v3 看板一致 |
| 横向图 | 草案允许 `orientation: "horizontal"` 用于 cartesian | 只允许类目 x 轴上的 bar 与 line；散点和数值 x 轴返回 `INVALID_ENCODING`（否则点坐标会画反） |
| 物理画像来源 | 草案 4.1 一度写“沿用 `columnTypes`” | 扫描全部行；产品查询执行器不返回列类型，`columnTypes` 是按首行推断的，不可靠（已修订进 ADR 与草案） |
| 版本记录 | ADR-0008 决策 9：持久化 ChartSpec、数据身份、编译器与主题版本，已交付报告保存产物 | `render_chart` 写出的 SVG 本身就是保存下来的产物，但**没有保存 ChartSpec，也没有记录编译器与主题版本**；聊天 widget 保存了 ChartSpec 与 `receiptId`，也没有版本。ADR 已修订出落地方式（旁路 `.chart.json` 与 widget 字段），尚未实现 |

## 7. 已知限制

- **只有 SVG。** PNG 需要 `@resvg/resvg-js`（原生依赖）和随应用分发的 CJK 字体，主要服务 docx 导出，尚未实现。
- **Python 算出的数据不能画图。** 派生数据集（`data.kind = "derived"`）没有登记路径，工具返回 `CHART_DATA_UNSUPPORTED`；需要画的量要在 SQL 中算出并发布。
- **字段语义只有模型声明。** 数据集注解存储未实现，编译时直接使用 spec 中的 `fields`（工具以 `[SEMANTICS]` 如实标注来源）。物理画像已生成，但还没有被用来做一致性检测（例如声明为 ratio 的列数值超出 [-1, 1]）。
- **每张图都要先完成 Answer Spec 再发布。** 这是 ADR-0008 决策 4 的既定成本，报告里 N 张图就要 N 次；ADR-0009 用来缓解。
- **看板没有改造。** `generate_dashboard` 仍走 `dashboard-v3.ts`（数据来自工作区 CSV 或 spec 内联的行）与只生成桥接壳的 `dashboard-v4.ts`；不经过发布记录，也不用 ChartSpec。
- **前端的 `echarts`/`config` widget 分支没有收紧**（ADR-0008 决策 11）。当前 Runtime 不会产出这种 kind，它只可能出现在更早的会话记录里。
- **CI 不跑分发构建和 web host 冒烟测试**，它们只在 `develop` 合入 `master` 前的本地 `verify:backend` 中运行。#90 修复的分发构建问题就是因此潜伏的。
- **聊天图表没有在运行中的应用里做过端到端截图验证。** 前端测试 mock 了 ECharts，断言传入的 option；浏览器端用的编译器与 SSR 相同，SSR 输出做过截图验证。

## 8. 下一步方向

按依赖关系和收益排序。标出了需要维护者拍板的决策。

1. **实现 ADR-0008 决策 9 的版本记录。** ADR 已修订（技术约束改为实测结论；决策 9 写明落地方式）。实现：`@data-agent/charts` 导出编译器与主题版本常量；`render_chart` 在 SVG 旁写 `charts/<name>.chart.json`（ChartSpec、`receiptId`、`contentHash`、版本、尺寸、展示提示，不含行）；`show_widget(chart)` 负载加版本字段。改动小，补上 `render_chart` 不保存 ChartSpec 的缺口。
2. **看板（第 4 步）。** 先决定：dashboard skill 与实现以哪一方为准（#79 已把 skill 收缩到现有实现，筛选、下钻、KTX 语义刷新是否要补，需要另写看板规格的 ADR）。然后把 v3/v4 合并为一种看板规格：views 由 ChartSpec、Table、KPI 组成；数据来自发布记录（快照）或语义查询绑定（实时，另立 ADR）；独立 HTML 内联 `@data-agent/charts` 并在页面里编译，而不是嵌入 option。
3. **数据集注解与一致性检测。** 以 `DatasetRef` 为键的只追加注解存储（ADR-0008 决策 3 的第二层），按证据权威解析，同级冲突返回 `SEMANTICS_CONFLICT`；用物理画像做一致性检测并以提示告知。注解模块放在 `@data-agent/charts` 内还是独立模块，需要决定（草案第 9 节倾向独立，供表格共用）。
4. **PNG 输出（第 2 步剩余部分）。** 需要决定：引入 `@resvg/resvg-js` 原生依赖，以及选用哪套可再分发的 CJK 字体（如 Noto Sans SC 子集）、打包体积上限。随后接入 electron-builder 与 `smoke-electron`。有 docx 导出需求时再做。
5. **派生数据集。** 为 Python 输出登记派生数据集（记录输入 Receipt 与计算来源），生成同结构的物理画像，让 `data.kind = "derived"` 可用。
6. **扩展图种（第 5 步）。** 热力图、箱线图、直方图、桑基图、树图、瀑布图；草案第 7 节已做纸面推演。按 ADR-0008 决策 7，对比自研模板与 Flint 适配后端，验收以数值、观测身份与分母一致为准。
7. **报告级任务（ADR-0009）。** 等 ADR-0007 落地，并先用真实报告度量逐图发布的实际成本。
8. **CI 补充分发构建。** 至少在目标为 `master` 的 PR 上运行 `build:distribution` 与 `smoke-web-host`。

## 9. 踩过的坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 独立 `.svg` 文件在浏览器中报 XML 错误，内联到 HTML 里却正常 | ECharts SSR 把字体栈原样写进双引号的 `style` 属性，不转义 | 字体栈用单引号；测试用 `saxes` 严格解析每张 SVG |
| 同样输入两次渲染的 SVG 不同 | zrender 的 id 与 class 带实例计数器（`zr0-c0`、`zr1-cls-2`） | 按内容哈希重命名。只在 `id="`、`class="`、`url(#`、`href="#` 与 CSS 选择器位置替换，否则会改写恰好长得像 id 的标签文字（#87 评审发现） |
| 横向图轴名、饼图标签、单系列图 y 轴名被裁掉 | 轴名默认放在轴末端、饼图标签默认截断、顶部留白不足 | 底部数值轴名居中放在轴下方并预留空间；饼图标签分两行并折行；顶部留白保证放下轴名。这些都是截图才发现的，单元测试没有覆盖到 |
| 横向散点坐标画反 | `orientation` 只交换了轴，没有交换点的 `[x, y]` | 横向只允许类目 bar/line（#83 评审发现） |
| CI 上 skill 全部加载为空，本地正常 | Windows runner 的临时目录是 8.3 短名 `RUNNER~1`，`realpath` 与原路径不相等，根目录被静默跳过 | 按 `realpath` 扫描根目录（#85）；本地可把 `TEMP` 指向一个 junction 来复现 |
| skill 示例测试读不到示例 | Windows 检出的文件是 CRLF | 测试先把 `\r\n` 统一成 `\n` |
| 前端“类型检查通过”其实什么都没检查 | `frontend/tsconfig.json` 是 `files: []` 加 references | 用 `npx tsc -p tsconfig.app.json --noEmit`；前端 `build` 脚本的 `tsc -b` 在 CI 中覆盖 |
| bigint 无法序列化进 widget | 发布结果可能含 bigint，widget 负载要以 JSON 持久化 | `jsonSafeRows`：bigint 转十进制文本、Date 转 ISO 文本，编译器能读回 |
| 模型拿不到 `receiptId` | 发布工具只在下载链接 URL 中间带着它 | 返回文本显式加 `receiptId=` |

## 10. 验证方法

- **开发中**：在包目录运行 `npx vitest run` 与 `npx tsc -p tsconfig.json --noEmit`（前端用 `tsconfig.app.json`）。
- **开 PR 到 `develop` 前**：全仓库 `npm run typecheck`、`npm test`；动了后端或包结构时加 `npm run verify:architecture`（其中包括“编译器只能 import 相对路径与 `@data-agent/contracts`”这条同构约束）。
- **`develop` 合入 `master` 前**：`npm run verify:backend`。
- **图表外观**：单元测试不能替代看图。用 `renderChartSvg` 把样例写到临时目录，再用本机 Edge 无头截图后查看，同时要单独打开 `.svg` 文件以检验 XML 合法性：

  ```bash
  "/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new --disable-gpu \
    --hide-scrollbars --window-size=660,420 --screenshot=C:\\path\\shot.png "file:///C:/path/chart.svg"
  ```

  实测应覆盖中文长标签、双轴组合、横向条形、环形饼图、散点，以及含 `&`、`<`、`"` 的标签。
