## 4. 阶段 A：验证缺口

### A1 日期与时区

**问题（未核实，优先验证）。** ADR-0008 的验收原则要求“日期不因时区偏移”。已核实的事实：`packages/mcp-mysql` 没有配置 `dateStrings`，mysql2 默认把 DATE/DATETIME 解析为本地时区的 `Date`，MCP 服务再经 `JSON.stringify` 输出为 UTC ISO 文本；编译器对 `temporal` 字段只做字符串排序（`compile.ts` 第 80 行），声明的 `zone` 没有被使用。据此推测，在 UTC+8 的机器上，`DATE '2025-12-01'` 可能以 `2025-11-30T16:00:00.000Z` 进入结果并显示在轴上。

**范围。**

1. 用真实 MySQL 核实 DATE、DATETIME、TIMESTAMP 三种列经产品查询路径进入 ResultStore 后的值。
2. 若确有偏移：在数据库 MCP 层修正（例如 `dateStrings`），使日历值以不带时区的文本进入结果；已发布的结果不改写。
3. 编译器按 `temporal.grain` 与 `zone` 格式化轴标签与 tooltip：`floating` 原样显示，带时区的时间戳按声明的时区显示，浏览器与 Node 结果一致。

**验收条件。**

- [ ] 有一个 `DATA_AGENT_TEST_MYSQL=1` 契约测试，覆盖 DATE、DATETIME、TIMESTAMP 在 UTC+8 与 UTC 两种进程时区下的取值，记录结论。
- [ ] `DATE '2025-12-01'` 在聊天图表、SVG、看板中都显示为 `2025-12`（月粒度）或 `2025-12-01`（日粒度），不出现前一天。
- [ ] 编译器测试在 `TZ=Asia/Shanghai` 与 `TZ=UTC` 下产出相同的 option；`version.test.ts` 的指纹若变化，按通用条件递增版本。
- [ ] 若核实后没有偏移，关闭本项并在转交文档中记录核实结论。

### A2 运行中应用端到端验证

**问题（已核实）。** 聊天图表的前端测试 mock 了 ECharts；看板只在 jsdom 与 Edge 无头模式中验证过，没有在应用的预览 iframe（`sandbox="allow-scripts ..."`，`srcDoc` 加载）里打开过。

**范围。** 在 web host 或 Electron 中跑一次完整流程：查询 → 发布 → `show_widget(chart)` → `render_chart` → `generate_dashboard`，并在预览中打开看板。

**验收条件。**

- [ ] 聊天图表在应用中渲染，展示提示、Disclosure、`[CHECK]` 显示在图下方；刷新会话后从历史记录重新编译，外观一致。
- [ ] `render_chart` 生成的 SVG 在应用的文件预览中正常显示。
- [ ] 看板在应用预览中渲染全部视图，控制台无错误；在沙箱 iframe 中打包的 schema 校验器可以运行（不依赖被沙箱禁用的能力）。
- [ ] 以上各截一张图附在 PR 中；发现的问题各自修复并补测试。
- [ ] 可自动化的部分纳入 `smoke-web-host` 或新的冒烟脚本；不能自动化的写成转交文档中的手工检查清单。

### A3 跨目标一致性测试

**问题（已核实）。** ADR-0008 的验收原则要求“同一数据版本在聊天、独立 HTML、SSR 中数值与单位一致”，目前没有测试直接比较三个目标。

**验收条件。**

- [ ] 一个测试用同一 ChartSpec 与数据集分别编译 `interactive`（聊天与看板共用）与 `static`（SVG），断言各系列的数值、类目顺序、轴名与单位文本一致。
- [ ] 同一个测试从生成的看板 HTML 中取出嵌入的数据，确认与聊天 widget 负载中的行逐一相同。
- [ ] 覆盖 ratio 与 percent 声明、量级换算、空值、Top-N 选择各一例。

### A4 CI 与本地检查

**问题（已核实）。** CI 不运行 `build:distribution` 与 `smoke-web-host`，#90 修复的问题因此潜伏过；`build-distribution.mjs` 漏掉 charts 构建的问题直到 #97 才补上。`check:affected` 的全量回退只计时过一次（364 秒），没有与原来的全仓 `typecheck` 加 `test` 做过同一提交的对比。

**范围。**

1. CI 在目标为 `master` 的 PR 上运行 `build:distribution` 与 `smoke-web-host`。
2. 在同一提交上计时 `npm run typecheck && npm test` 与 `npm run check:affected -- --all`，据结果处理全量回退：若更慢，全量回退改为调用原来的根脚本。
3. 收窄回退规则：只有根 `package.json` 与 lockfile 触发全量，`scripts/` 下的文件按用途映射。

**验收条件。**

- [ ] 目标为 `master` 的 PR 上 CI 运行分发构建与 web host 冒烟测试，并在一次真实的 `develop` → `master` PR 上通过。
- [ ] 计时结果（两种方式各至少一次，同一提交、同一机器）写进 PR 描述。
- [ ] `check:affected --all` 的耗时不超过原来的全仓检查。
- [ ] 只改 `scripts/verify-backend-architecture.mjs` 时，`check:affected` 只运行架构检查；`scripts/check-affected.test.mjs` 覆盖新规则。

## 5. 阶段 B：遗留路径收口

### B1 收紧前端 `echarts` widget（ADR-0008 决策 11）

**问题（已核实）。** `frontend/src/api/chat-events.ts` 仍接受 `echarts` kind，`WidgetRenderer` 的 `echarts` 分支直接 `setOption(widget.config)`。当前 Runtime 不会产出这种 kind。

**验收条件。**

- [ ] 新会话中的 `echarts` kind 事件不再被渲染为图表，而是显示“不支持的历史图表”说明；该判断依据 Runtime 的产出记录（`contractVersion`、`tool_call_id` 与 `show_widget` 的对应关系），而不是模型可以填写的字段。
- [ ] 历史会话中已存在的 `echarts` widget 按决策 11 保留只读展示，或明确提示不支持；测试覆盖两种情况。
- [ ] 前端测试中涉及 `echarts` kind 的用例相应更新。

### B2 清理 v3 看板残留入口

**问题（已核实）。** `generate_dashboard` 工具已只接受新规格，但协议命令 `dashboard.generate`（`protocol.ts`）仍可生成 v3 与 v4 看板；`dashboard.v3.data` 命令与 `GlobalPreviewModal` 的参数变更处理只服务于 v3 页面，后者发回的数据恒为空。前端没有调用 `dashboard.generate`。

**验收条件。**

- [ ] 协议命令 `dashboard.generate` 的 v3 分支移除，或改为调用新规格的同一条路径（经 Receipt 鉴权）；v4 分支按 E1 的结论处理，在此之前保持冻结。
- [ ] 已生成的 v3 HTML 仍能在预览中打开（它们自带数据与脚本）。
- [ ] 删除不再有调用方的代码与测试；`dashboard-migration.ts` 随 v4 一起留到 E1。
- [ ] 架构检查与现有测试通过，删除的协议命令在 PR 描述中注明。

### B3 移除 Python 运行时中的 matplotlib

**问题（已核实）。** skill 已不再用 matplotlib 画图，但 `scripts/build-python-runtime.mjs` 与 `scripts/smoke-python-runtime.mjs` 仍要求 matplotlib 可以导入。ADR-0008 的后果一节预期迁移完成后移除它以缩小分发体积。

**决策（2026-09-29）。** 移除。`run_python` 中导入 matplotlib 会失败；交付图表只走 ChartSpec。

**验收条件。**

- [ ] 构建与冒烟脚本不再要求 matplotlib，Python 运行时的依赖清单中不再包含它。
- [ ] Python 运行时体积变化写进 PR 描述；仓库中没有剩余的 matplotlib 导入。
- [ ] `run_python` 的工具提示与相关 skill 写明不提供绘图库，模型需要图表时使用 `render_chart`、`show_widget` 或 `generate_dashboard`。
- [ ] `verify:backend:packaged` 在 Windows 上通过。

## 6. 阶段 C：能力扩展

### C1 派生数据集

**问题（已核实）。** `DatasetRef` 的 `derived` 分支已在契约中，但 `render_chart`、`show_widget`、`generate_dashboard` 都对它返回 `CHART_DATA_UNSUPPORTED`；Python 算出的量目前不能画图。

**范围。** Runtime 为 `run_python` 的输出登记派生数据集：记录输入的 Receipt 列表、计算来源（脚本内容哈希、运行时版本）、输出行；生成与发布结果同结构的物理画像；数据解析层按 `derivedId` 返回行并检查访问权限。

**验收条件。**

- [ ] 派生数据集不可变：同一 `derivedId` 再次读取得到相同的行与内容哈希；登记后修改工作区文件不影响它。
- [ ] 只能由 Runtime 登记，模型不能提交任意行冒充派生数据集；输入必须是当前会话可访问的 Receipt。
- [ ] 三个图表入口都接受 `{ kind: "derived", derivedId }`，图注或页面标明“派生自 <receiptId 列表>”并附上输入结果的 Disclosure。
- [ ] 派生数据集带物理画像，一致性检测（`[CHECK]`）对其同样生效。
- [ ] 契约测试覆盖：伪造 `derivedId`、跨会话访问、输入 Receipt 不可访问三种拒绝情况。

### C2 PNG 输出（挂起）

**决策（2026-09-29）。** 挂起，有明确的 docx/pdf 交付需求时再做。届时再决定是否引入 `@resvg/resvg-js`（napi 原生依赖）、随应用分发哪套 CJK 字体（例如 Noto Sans SC 子集）、安装包体积增量上限。

**进入条件。** 出现需要位图图表的交付需求（通常是 docx 导出）。

**验收条件。**

- [ ] `render_chart` 可以输出 PNG，与 SVG 来自同一次编译，旁路记录写明格式。
- [ ] PNG 使用随应用分发的字体渲染，在没有安装中文字体的干净 Windows 环境中中文正常显示（`run-clean-env-gates` 或等价检查）。
- [ ] 中文长标签、双轴、横向条形、环形饼图、散点五类样例截图检查通过，没有溢出、重叠或方块字。
- [ ] 原生依赖纳入 electron-builder 与 `smoke-electron`；安装包体积增量不超过决策给出的上限。
- [ ] 若实测字宽偏差明显，按 ADR-0008 技术约束引入真实字体度量，并递增主题或编译器版本。

### C3 报告导出（ADR-0008 决策 10，挂起）

**问题（已核实）。** Runtime 中没有 docx 或 pdf 导出；报告目前是模型写的 Markdown，引用 `charts/*.svg`，图注由模型按提示抄写。

**决策（2026-09-29）。** 与 C2 一起挂起。需求出现时再决定报告是否采用决策 10 的“文档块 + 图表块”结构，以及首期导出格式。

**进入条件。** 与 C2 相同。

**验收条件。**

- [ ] 报告中的图表块为 `{ chart: ChartSpec, dataset: DatasetRef }`，导出时由 Runtime 渲染，不依赖模型抄写图注。
- [ ] 导出的图注自动包含展示提示、Disclosure、`[CHECK]` 与语义来源说明。
- [ ] docx 使用 C2 的 PNG；导出结果在 Word 中打开无修复提示。
- [ ] 同一报告两次导出的图表数值相同，旁路记录可以追溯每张图的 Receipt 与版本。

## 7. 阶段 D：扩展图种（ADR-0008 第 5 步）

按草案第 7 节的纸面推演逐个实现，每个图种一个 PR。按 ADR-0008 决策 7，第一个图种实现前先对比自研模板与 Flint 适配后端，结论写进该 PR。

**颜色规则（2026-09-29 决定）。** `series.colors` 保持任意 `#RRGGBB` 色值，不限制为主题语义色；ChartSpec v1 不变。新图种的颜色通道沿用同一规则，缺省使用主题调色板。

| 编号 | 图种 | 需要新增的错误码或约束（草案） |
| --- | --- | --- |
| D1 | 热力图 | 两个类目轴加颜色通道；编码组合唯一（`DUPLICATE_KEY`）；发散中点须声明 |
| D2 | 直方图、箱线图 | 分箱与四分位数由查询提供；`BIN_OVERLAP`、`STAT_ORDER_VIOLATION` |
| D3 | 瀑布图 | 累计值由查询提供；`RANGE_INCONSISTENT` |
| D4 | 桑基图、树图 | 非平表数据形态；`FLOW_CYCLE`；属于部分与整体，要求可加、完整、非负 |

**每个图种的验收条件。**

- [ ] ChartSpec 的 `chart` 联合新增成员，不修改已有成员；`checkChartSpec` 只报告所声明图种的错误。
- [ ] 编译器不聚合、不计算统计量：图上显示的每个数都能在数据集中找到对应单元格（部分与整体图种的视觉求和除外）。
- [ ] 新错误码有正反两例测试；展示提示覆盖高基数、空值、负数。
- [ ] `interactive` 与 `static` 两个目标都有截图检查（中文长标签、固定画布）；A3 的跨目标一致性测试加入该图种。
- [ ] 看板的 `chart` 视图自动支持该图种，skill 示例经校验器测试。
- [ ] 按通用条件递增编译器版本并新增指纹。
- [ ] 若采用 Flint：适配器关闭其聚合，overflow 纳入展示提示；验收以数值、观测身份、分母一致为准；Flint 的结构不进入 ChartSpec。

## 8. 阶段 E：另立 ADR 或依赖外部

这些事项需要先有新的 ADR 或外部前提，本计划只给出进入条件与完成标准。

### E1 看板实时绑定

**决策（2026-09-29）。** 需要，尽快起草 ADR。ADR 起草可以与阶段 A 并行，实现排在 C1 之后、阶段 D 之前。

**ADR 须回答的问题。**

- 作为新 `DatasetRef` kind 的数据绑定形式：绑定语义查询还是绑定已有的 Answer Spec，刷新时是否重新经过 Query Assurance 与发布。
- 数据版本与更新时间如何记录和展示；刷新失败时页面显示什么。
- 刷新后的重新校验与展示提示、`[CHECK]` 的更新规则。
- 宿主桥接协议：页面与应用之间的消息、鉴权与来源校验；独立 HTML 离开应用后如何表现（只显示最后一次快照）。
- 冻结的 `dashboard-v4.ts`、`dashboard-migration.ts`、`dashboard.v3.data` 与 `GlobalPreviewModal` 参数变更处理的去留（与 B2 衔接）。

**起草前先核实的前提。** 语义查询当前的执行路径与鉴权方式；v4 桥接壳与 `GlobalPreviewModal` 现有的消息协议；Electron 与 web host 两种宿主中预览 iframe 的差异。

**验收条件。**

- [ ] 新 ADR 被接受，并在开头列出它修订的 ADR-0008 条款。
- [ ] DashboardSpec 只新增 `DatasetRef` kind，已有快照看板不受影响。
- [ ] 每次刷新都经 Runtime 鉴权并重新校验；展示提示、`[CHECK]` 随刷新重新计算，不沿用过期内容。
- [ ] `dashboard-v4.ts`、`dashboard-migration.ts` 与相关协议命令按 ADR 的结论删除或替换。

### E2 数据集注解存储

**进入条件。** 出现高于模型声明的字段语义来源（已审定的业务定义、语义模型，或 ADR-0007 落地后的字段）。

**验收条件。**

- [ ] 注解以 `DatasetRef` 为键、只追加，每条带依据；按证据权威解析。
- [ ] 同一来源的后续声明可以取代先前声明，只对不同来源的同级冲突返回 `SEMANTICS_CONFLICT`（ADR-0008 决策 3 首期说明）。
- [ ] 图表旁路记录与 widget 负载记录所采用的注解版本；更高权威注解出现后，已交付图表不自动改变。
- [ ] `[SEMANTICS]` 提示按实际来源显示（业务定义或模型声明）。

### E3 报告级任务（ADR-0009）
