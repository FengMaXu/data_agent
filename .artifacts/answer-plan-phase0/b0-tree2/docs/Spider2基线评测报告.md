# Data Agent Spider2-Lite 基线评测报告

## 1. 结论摘要

本轮完成了 Spider2-Lite 全部 **135 个 SQLite 任务**，Agent、模型、Prompt、Skills、Runtime、数据库工具和评测数据均已冻结。运行期间没有余额或供应商基础设施故障。

官方评测给出 `38/135 = 28.15%`，但事后审计发现两处评分工件异常：

1. 9 个超时任务的最后一次工具调用尚未结束，却被当成成功调用提取为最终 SQL；其中 `local032` 因此被 SQL evaluator 判为正确。
2. `local275.csv` 是 0 字节空文件，却被官方 exec-result evaluator 判为正确。

使用“最后一次**已完成且成功**的 SQL 调用”重新生成 SQL 提交，并排除 0 字节 CSV 后，官方 evaluator 的审计结果为：

| 指标 | 官方原始结果 | 审计后结果 |
|---|---:|---:|
| SQL EX（固定135题） | 38/135 = 28.15% | **37/135 = 27.41%** |
| E2E EX（已提交） | 38/112 = 33.93% | 37/111 = 33.33% |
| E2E EX（固定135题） | 38/135 = 28.15% | **37/135 = 27.41%** |

因此，建议将本轮正式基线登记为：

> **Spider2-Lite SQLite audited E2E EX = 27.41%（37/135）**

该成绩衡量的是当前完整 Agent 系统，而不是单独衡量模型。

## 3. 核心发现

### 3.1 任务无法正常收敛是第一类瓶颈

41/135（30.37%）任务未正常结束：

- max_turns：25题
- timeout：16题
- 审计后这些题的 E2E 正确数：0

23个原始任务没有 CSV；加上 `local275` 的0字节文件，实际有24题没有有效交付。

正常完成的94题中，审计后仅37题正确，正确率为39.36%。这说明增加时间或轮次不能单独解决问题：即使任务正常结束，仍有57题结果错误。

### 3.2 大量任务停留在中间结果，没有形成最终答案

在74个“已导出但错误”的任务中：

- 54题结果行数与 Gold 不一致；
- 56题列数与 Gold 不一致；
- 64题至少存在行数或列数不一致，占86.49%；
- 31题的 Gold 仅需1行，但 Agent 导出了多行中间明细。

典型案例：

- `local009`：最长距离已在第一行，但导出全部距离；
- `local010`：生成全部区间统计，未继续取最小区间；
- `local017`：生成各年Top原因，未继续找异常年份；
- `local020`：第一名正确，但导出282名选手；
- `local034`：生成各品类支付次数，未继续计算平均值；
- `local329`：返回符合条件的session，而问题要求session数量。

这不是某一道题的知识缺失，而是通用的“最终答案契约”缺失。

### 3.3 SQL Guard 对合法分析SQL误杀严重

273次工具错误中，122次为 `FORBIDDEN_SQL`：

- 104次：只读 `UNION/UNION ALL SELECT` 被拒绝；
- 9次：只读查询中的 `REPLACE()` 函数被当成写操作；
- 9次：真实多语句查询，应当被拒绝。

即 **113/122（92.62%）的安全拦截属于误杀**，占全部工具错误的41.39%。

涉及 Guard 错误的45题平均耗时80.7秒；未涉及的90题平均耗时49.3秒。Guard 错误题的审计正确率约8.9%，明显低于无 Guard 错误题的36.7%。这是相关性证据，不等同于全部因果，但足以将其列为首要工具缺陷。

### 3.4 工具可见性与实际能力不一致

- `run_python` 被调用27次，失败27次，错误率100%；
- 涉及23题，其中仅1题正确；
- `show_widget` 被调用15次，失败7次，而Spider2任务并未要求图表；
- `analysis` Skill在8道纯SQL任务中被激活。

Agent能够看到这些能力，却无法成功使用或没有必要使用，造成额外轮次、错误和上下文污染。评测结果说明当前工具路由和能力声明不一致。

### 3.5 SQL方言与Schema使用不稳定

工具错误还包括：

| 错误类型 | 次数 |
|---|---:|
| SQLite不支持的函数 | 37 |
| SQL语法/表达式错误 | 36 |
| 表或字段错误 | 25 |
| 错误的元数据/方言查询 | 11 |

高频误用包括 `YEAR`、`MONTH`、`DATEDIFF`、`DATE_FORMAT`、`SUBSTRING_INDEX`、`information_schema` 等MySQL语法。虽然评测知识文件声明了SQLite后端，但这一信息没有稳定进入SQL生成决策。

### 3.6 聚合粒度和数值语义仍是主要正确性问题

10个错误任务与Gold具有相同结果形状，但数值仍不正确，代表更纯粹的语义错误。代表案例：

- `local024`：球员平均值和国家平均值的计算粒度错误；
- `local061`：按产品/月增长率投影与汇率转换口径错误；
- `local062`：利润分桶边界和实体聚合错误；
- `local114`：订单数受到明细连接重复影响；
- `local156`：比特币单位成本计算和年度变化口径错误；
- `local196`：首单识别和后续租赁计数存在偏差；
- `local299`：滚动窗口和月度基准处理错误；
- `local358`：年龄区间边界错误。

这些问题适合通过通用的粒度、连接基数、浮点除法和窗口边界规则改进，不能加入针对具体题目的Skill提示。

## 4. 效率与正确率关系

审计前后不影响以下总体趋势：

| 分组 | 题数 | 官方E2E正确数 | 正确率 |
|---|---:|---:|---:|
| 无工具错误 | 49 | 23 | 46.94% |
| 1–2次工具错误 | 42 | 11 | 26.19% |
| 3–5次工具错误 | 28 | 2 | 7.14% |
| 6次及以上 | 16 | 2 | 12.50% |

正确任务平均约9.6轮、11.9次工具调用；错误任务平均约14.8轮、20.8次工具调用。当前Agent在错误路径上往往持续探索，而不是更早回退、重规划或停止。

## 5. 评分与评测器问题

本轮运行工件完整，但评测适配器仍需在下一次实验前修复：

1. `selectFinalSql`必须要求工具调用存在`finishedAt`且成功，不能选择被timeout中断的调用；
2. 0行导出必须生成带列头的CSV，0字节文件不能视为有效交付；
3. 正式评分应拒绝0字节CSV；
4. `maxTurns=20`当前在第21轮才触发，应统一轮次定义；
5. SQL evaluator单轮评分耗时约2小时16分，应增加逐题ID、耗时和异常记录。

审计工件：

- `audit_submissions/sql/`
- `audit_submissions/csv/`
- `audit_score/sql.log`
- `audit_score/exec_result.log`

## 6. 改进优先级

### P0：先修评测与工具基础设施

1. 修复最终SQL/CSV提取规则和0字节CSV评分；
2. 修改SQL Guard：允许单条只读CTE中的`UNION/UNION ALL`，允许表达式函数`REPLACE()`，继续禁止真实多语句和写操作；
3. 保证`run_python`真实可用，或在不可用环境中不暴露该工具；
4. 纯查询任务不应自动调用`show_widget`或激活可视化Skill。

### P1：增加通用最终答案契约

在导出前检查：

- 用户最终要求的是标量、Top-N、分组表还是明细；
- 当前结果行数、列数和粒度是否与要求一致；
- 是否仍停留在中间CTE或中间统计；
- 是否完成最后一次聚合、差值、排名过滤或投影；
- 导出的SQL是否就是最后一次已验证SQL。

该机制必须是通用能力，不能包含Spider2题目答案或特定字段规则。

### P2：增强方言与语义控制

1. 数据库工具元数据中显式提供当前方言；
2. SQL生成前确认实体粒度和一对多连接；
3. 平均值和比率显式使用浮点除法；
4. 窗口函数明确frame、排序和tie-breaker；
5. 对时间边界、Top-N并列和NULL处理进行最终自检。

## 7. 建议的实验顺序

保持本基线和Agent冻结，按单变量A/B执行：

1. **实验A：仅修SQL Guard**，在45个受影响案例及独立holdout上复测；
2. **实验B：仅修工具可用性/路由**，验证Python失败、Widget误调用和轮次变化；
3. **实验C：加入通用最终答案契约**，重点观察74个已导出错误任务的形状匹配率；
4. **实验D：加入方言与粒度自检**，重点观察同形状数值错误集；
5. 每项改动通过Regression Set后，再跑完整135题确认，禁止将单题修复直接写入Prompt或Skill。

建议主要验收指标：

- Audited E2E EX（固定135分母）；
- 正常完成率；
- 有效CSV交付率；
- 工具错误数及Guard误杀数；
- 结果形状匹配率；
- 平均工具调用和P90耗时。
