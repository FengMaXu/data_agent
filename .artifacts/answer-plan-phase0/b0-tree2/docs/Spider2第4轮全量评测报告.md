# Spider2 第 4 轮全量评测报告

## 1. 结论摘要

第 4 轮 SQLite 全量评测完成 **135/135** 题，没有基础设施失败。以固定 135 题为分母，端到端（E2E）正确题从第 3 轮的 **49 题（36.30%）** 增至 **55 题（40.74%）**，净增 **6 题 / 4.44 个百分点**；SQL 正确题从 49 增至 **56 题（41.48%）**，净增 **7 题 / 5.19 个百分点**。

交付闭环和完成率也改善：CSV 生成从 116 增至 123，完成状态从 115 增至 123，`max_turns` 从 12 降至 1。不过，工具错误从 61 增至 125，主要是新增的 `EXPORT_SQL_NOT_VALIDATED` 保护在 67 题中拒绝“预览后改写”的导出 SQL。该保护并非空白字符或末尾分号造成的格式误差：67 次拒绝中没有一次仅存在这两类差异；其中 65 次最终仍完成 CSV 交付。未使用 SQL AST/执行等价性比较，因此本报告不把所有差异一概断言为语义变化。

因此，本轮证明“探索预算 + 交付提醒 + 导出前形状/预览一致性校验”总体提高了可交付正确结果的数量，但导出阶段的重试成本和基础 SQL 语义错误仍是下一轮首要问题。

## 5. 工具错误与保护机制分析

基于每题 `trace.json` 中的实际工具调用分类：

| 错误类别 | 第 3 轮 | 第 4 轮 | 解释 |
|---|---:|---:|---|
| `EXPORT_SQL_NOT_VALIDATED` | 0 | 67 | 第 4 轮新增的“导出 SQL 必须是同会话最后成功预览 SQL”保护 |
| `MCP_TOOL_ERROR` 查询错误 | 37 | 50 | SQL 语法、列名和业务推理错误仍是最大原始错误源 |
| `FORBIDDEN_SQL` | 5 | 6 | 多语句/安全规则误触发基本持平 |
| MCP 请求超时错误 | 5 | 2 | 下降 3 次 |
| 知识文件 `ENOENT` | 9 | 0 | 已消除 |
| 不存在的工具名调用 | 4 | 0 | 已消除 |

### 预览—导出一致性校验的实际表现

- 共触发 `EXPORT_SQL_NOT_VALIDATED`：67 次，覆盖 67 个题目。
- 与最后一次成功预览 SQL 对比：**0 次**只存在空白字符或末尾分号差异；67 次均超出当前规范化规则的容忍范围。
- 被拒绝后最终生成 CSV：65/67；未恢复交付的是 `local063` 与 `local220`。
- 其中最终得到 E2E 正确：28/67。

该结果证明校验有效拦截了“预览结果与最终导出不一致”的真实风险，并且绝大多数任务能够恢复；但它也在近半数题目中增加一次或更多次工具往返，是平均工具调用和平均时长上升的重要候选因素。该结论是运行轨迹相关性，不是严格因果证明。

本轮没有记录到 `SHAPE_MISMATCH`。这只能说明本次导出调用没有触发形状断言，不等同于结果粒度问题已经消失；官方 E2E 仍有 80 题未正确。

## 6. 建议的下一步

1. **保留导出 SQL 一致性校验，不要为降低错误数而移除。** 67 次拒绝均为实质 SQL 改写，移除会重新允许“预览正确、导出错误”的交付风险。
2. **降低校验后的恢复成本。** 将交付阶段的提示收敛为固定序列：先执行最终 SQL 的一次 `query_database` 预览，再原样调用 `export_query`；并在校验失败提示中明确要求停止重写、先预览导出 SQL。目标是减少无效的 export→reject→再探索循环。
3. **优先审计 6 个 E2E 回归题。** `local026` 先处理超时/CSV 缺失；`local017`、`local021`、`local195`、`local274`、`local284` 逐题检查题目约束表、连接基数、时间边界和结果粒度。
4. **将 SQL 语义错误作为主攻方向。** 第 4 轮仍有 50 次 MCP 查询错误，且已交付但 E2E 错误的题目有 68 个。下一轮优先针对列名/方言错误、聚合粒度、JOIN 放大、分子分母事件集合和窗口基线期进行轨迹审计。
5. **用重复评测确认提升。** 由于模型调用非确定、并发由 3 调到 4，建议在相同运行时快照和相同并发下至少重复 3 次 135 题运行，报告均值、范围和每题翻转率，再据此判断本轮的真实稳定收益。
