# Tool Search 与首字可见延迟优化方案

## 背景判断

当前每次用户发新消息时，后端都会重新构造一次模型请求。即使不是进程首次调用 LLM，也会重新携带系统提示词、历史消息和完整工具 schema。工具数量增长后，首轮请求的输入体积与供应商侧预处理时间都会放大，表现为 `first_text` 长时间无输出。

Claude Code 的 ToolSearchTool 思路是：默认只给模型一个工具目录检索工具，其他工具作为 deferred tools 存放在运行时目录中。模型先用 `tool_search` 按意图或精确名称选工具，后端再把匹配工具的完整 schema 加入下一轮 LLM 调用。

## 目标

1. 前端发出用户消息后，后端立即通过 SSE 输出一段可见文本，不等待工具构建或 LLM 首 token。
2. 首轮 LLM 请求只携带 `tool_search` schema，避免每次会话开始都塞入全部工具 schema。
3. 模型通过 `tool_search` 动态加载匹配工具，下一轮 LLM 才看到这些工具的完整 schema。
4. 历史工具调用不能因为当前模型可见工具减少而被上下文清洗误删。
5. 新链路必须可回退、可观测、可测试，不能只做硬编码规则路由。

## 生产级设计

### 1. 即时可见文本

`event_generator` 在 `run_start` 和 `status(preparing)` 后立刻发送一个 `text_delta`：

```json
{"type":"text_delta","content":"收到，我正在分析请求并检索可用工具。\n\n"}
```

该事件不携带 `message_id`。前端已有 pending agent message，收到无 `message_id` 的 `text_delta` 时会写入 pending 气泡；后续真实 LLM `message_start` 到达时，前端把 pending 气泡重命名为真实消息 ID，继续追加 LLM 输出。这样用户立即看到反馈，同时不会创建额外的孤立 assistant message。

计时上新增 `first_visible_text`，保留 `first_text` 表示真实 LLM 首字，便于继续定位模型侧耗时。

### 2. ToolSearchCatalog

新增后端运行时目录对象 `ToolSearchCatalog`：

- 保存完整工具列表与稳定顺序。
- 暴露内置 `tool_search` 工具。
- 维护已加载工具集合。
- 首轮 `visible_tools()` 只返回 `tool_search`。
- `known_tools()` 返回 `tool_search + 全量工具`，供历史消息清洗使用。
- `tool_search` 支持：
  - `select:<tool_name>` 精确加载。
  - 普通自然语言关键词检索。
  - `+term` 必选词。
  - 英文、snake_case、camelCase、中文连续文本的通用分词/匹配。
  - 匹配工具名称、label、description、参数名和参数说明。

该实现是工具目录检索，不是规则路由；它不替模型决定业务流程，只负责按模型表达的意图返回并加载候选工具。

### 3. Agent 上下文拆分

`AgentContext.tools` 只表示本轮模型可见工具。

`AgentContext.tool_catalog` 保存完整目录。agent loop 每次 LLM 调用前刷新：

```text
context.tools = context.tool_catalog.visible_tools()
tool_defs = [tool.to_definition() for tool in context.tools]
```

`AgentContextBuilder` 新增 `known_tools` 参数。历史消息清洗用 `known_tools` 判断工具调用是否合法，模型请求只用 `tools` 中的可见工具 schema。

### 4. 回退与错误处理

- 如果模型误调未加载工具，工具错误提示会明确建议先调用 `tool_search` 或 `select:<tool_name>`。
- 如果 `tool_search` 无匹配，会返回可读提示，不中断 agent。
- 如果工具目录为空，模型仍可看到 `tool_search` 并得到空结果，直接文本回答不受影响。

### 5. 可观测性

计时与日志新增：

- `first_visible_text`
- `full_tool_count`
- `model_tool_count`
- `deferred_tool_count`
- tool catalog 可见工具刷新记录
- tool search 匹配数量、新加载数量、已加载数量

### 6. 验证标准

1. 单元测试覆盖 `tool_search` 精确加载、关键词加载、中文意图匹配、可见工具刷新。
2. 上下文构建测试覆盖：当前可见工具只有 `tool_search` 时，历史 `execute_sql` 调用不会被删除。
3. SSE 测试覆盖：`run_start/status` 后，在 LLM 前先出现即时 `text_delta`。
4. 现有 widget/progress/缓存相关测试保持通过。
